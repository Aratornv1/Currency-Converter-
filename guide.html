Currency Converter: розбір ООП-версії

Конвертер валют на Express і TypeScript, переписаний із функцій-замикань на класи: value object-и, інтерфейс постачальника курсів, кеш як окремий клас, ієрархія помилок і ін'єкція залежностей. Нижче видно, що робить кожен клас, чому код розкладено саме так і як це перевіряють тести.

1. Що змінилось і навіщо

Раніше вся логіка жила у функції createRatesService(): вона створювала кеш, завантажувала курси, ділила запити й конвертувала суми, а замикання ховало внутрішні змінні. Валідацію робили функції, що повертали { ok, data } або { ok, error }. Тепер у проєкті класи, кожен із однією роллю. Відповіді API не змінились: 18 запитів до старої й нової версії дають однакові відповіді (див. «Що перевірено»).

Чи завжди класи кращі за функції?

Ні, і стара версія була робочою. Це навчальна переробка: вона показує, як виглядають інкапсуляція, успадкування, поліморфізм, інтерфейси та ін'єкція залежностей у справжньому коді. У кожному розділі нижче є пояснення, що саме це дає.

3. ООП-ідеї на цьому коді

ІдеяДеПростими словами
Інкапсуляція#entries у RatesCache, #inFlight у RatesService, private constructor у CurrencyCode, Amount, Conversionвнутрішній стан сховано; ззовні лише методи. Приватний конструктор означає, що створити об'єкт можна тільки через parse чи of.
НаслідуванняValidationError extends AppError extends Errorспільна поведінка (статус, ім'я) в предку, нащадок додає свій статус і текст.
Інтерфейс і поліморфізмRatesProvider ← ExchangeRateApiProvider (і StaticProvider у тесті)RatesService викликає fetchRates(), не знаючи, хто саме відповість: справжній API чи заглушка.
Композиція та ін'єкція залежностейnew RatesService(provider, cache), new ConverterApp(rates)об'єкт отримує потрібні йому частини ззовні, а не створює їх сам. Замінити кеш чи провайдер можна без правок сервісу.
Value objectCurrencyCode, Amountмаленький незмінний об'єкт, який не може бути неправильним: перевірка при створенні.
Фабрика і SingletonRatesService.create(), RatesService.shared()статичні методи класу: перший будує новий сервіс, другий тримає один спільний.
private проти #: два види «приватного»

У TypeScript private x — лише підказка для компілятора: у готовому JavaScript поле видно. #x — справжнє приватне поле мови, до нього не дістатись навіть з консолі. Тут # стоїть там, де стан небезпечно чіпати (кеш, список запитів у польоті), а private — для залежностей із конструктора.

4. Шлях одного запиту

Запит: GET /api/convert?from=usd&to=UAH&amount=12.5.

  1. server.ts створює ConverterApp(RatesService.shared()). Express викликає controller.convert.
  2. Контролер перетворює параметри на об'єкти: CurrencyCode.parse('usd','from') → USD, те саме для to, Amount.parse('12.5'). Неправильний ввід кидає ValidationError (400).
  3. RatesService.convert(from, to, amount) просить getRates(from). Спершу дивиться в RatesCache: свіжий знімок є — віддає його.
  4. Нема в кеші: перевіряє #inFlight. Якщо такий запит уже йде, чекає на нього, а не робить ще один.
  5. Інакше викликає provider.fetchRates(base). ExchangeRateApiProvider ходить в API, перетворює статуси та сире тіло на RatesSnapshot і час життя.
  6. Сервіс кладе знімок у кеш і віддає його. Якщо провайдер упав, а старий знімок є, віддає старий.
  7. Conversion.of(snapshot, to, amount) знаходить курс (або кидає UnknownCurrencyError) і рахує результат.
  8. res.json(conversion) викликає conversion.toJSON(). Помилка на будь-якому кроці потрапляє в ErrorHandler і стає { error } з правильним статусом.

5. Помилки й ErrorHandler

src/errors.tsнаслідування
// Ієрархія помилок: кожна несе готовий HTTP-статус, тож ErrorHandler просто віддає її клієнту.
//
//   Error
//    └─ AppError (status)
//        ├─ ValidationError       400  поганий ввід користувача
//        ├─ UnknownCurrencyError  404  такої валюти немає
//        └─ ProviderError         502  проблема на боці постачальника курсів
export class AppError extends Error {
  constructor(
    message: string,
    readonly status: number,
  ) {
    super(message);
    this.name = new.target.name; // імʼя реального класу: ValidationError, ProviderError, ...
  }
}

export class ValidationError extends AppError {
  constructor(message: string) {
    super(message, 400);
  }
}

export class UnknownCurrencyError extends AppError {
  constructor(code: string) {
    super(`Unknown currency: ${code}`, 404);
  }
}

export class ProviderError extends AppError {
  constructor(message: string) {
    super(message, 502);
  }
}
src/ErrorHandler.tsєдине місце відповідей про помилки
import type { NextFunction, Request, Response } from 'express';
import { AppError } from './errors';

// Єдине місце, де помилки стають HTTP-відповідями.
export class ErrorHandler {
  // Невідомий /api-шлях: JSON, а не HTML-сторінка Express
  notFound = (_req: Request, res: Response): void => {
    res.status(404).json({ error: 'Route not found' });
  };

  // Express розпізнає middleware помилок за чотирма параметрами, тому _next потрібен, хоч і не використовується
  handle = (err: unknown, _req: Request, res: Response, _next: NextFunction): void => {
    if (err instanceof AppError) {
      res.status(err.status).json({ error: err.message }); // очікувана помилка: статус уже в самій помилці
      return;
    }
    console.error(err); // баг: деталі лише в лог, клієнту загальне повідомлення
    res.status(500).json({ error: 'Internal server error' });
  };
}
  • Статус вшито в клас. Хто кидає new UnknownCurrencyError('XXX'), не думає про 404: він сам відомий класу. Раніше кожне місце мало передавати (message, 404).
  • err instanceof AppError у ErrorHandler покриває всі три нащадки одним порівнянням. Усе інше вважається багом: деталі в лог, клієнту «Internal server error».
  • Валідація тепер теж помилка. Раніше контролер перевіряв from.ok, to.ok, amount.ok і сам складав відповіді 400. Тепер parse кидає ValidationError, а контролер це не ловить: Express 5 передає відхилення async-обробників в обробник помилок сам.
  • Стрілкові поля (handle = (err, …) => …) не втрачають this, коли Express викликає їх як звичайні функції.

6. Value object-и: CurrencyCode і Amount

src/CurrencyCode.tsvalue object
import { ValidationError } from './errors';

// Код валюти (USD, UAH…). Value object: створити його можна лише через parse, а parse
// пропускає тільки 3 великі латинські літери. Тож якщо в руках є CurrencyCode, він правильний.
export class CurrencyCode {
  // field — назва параметра запиту, щоб повідомлення було точним («from is required»)
  static parse(value: unknown, field: string): CurrencyCode {
    if (typeof value !== 'string') throw new ValidationError(`${field} is required`);
    const code = value.trim().toUpperCase();
    if (!/^[A-Z]{3}$/.test(code)) throw new ValidationError(`${field} must be a 3-letter currency code`);
    return new CurrencyCode(code);
  }

  // Для внутрішнього коду, де відомо, що значення правильне (наприклад, базова валюта USD)
  static of(code: string): CurrencyCode {
    return CurrencyCode.parse(code, 'code');
  }

  private constructor(readonly value: string) {}

  equals(other: CurrencyCode): boolean {
    return this.value === other.value;
  }

  toString(): string {
    return this.value;
  }
}
src/Amount.tsvalue object
import { ValidationError } from './errors';

// Сума до конвертації. Value object: правильна за побудовою (невідʼємне число не більше MAX).
export class Amount {
  // Більше за це float уже втрачає точність
  static readonly MAX = 1e12;

  static parse(value: unknown): Amount {
    if (typeof value !== 'string' || value.trim() === '') throw new ValidationError('amount is required');
    // Number('1e3') = 1000, Number('0x10') = 16: приймаємо лише звичайний запис 12 або 12.5
    if (!/^\d+(\.\d+)?$/.test(value.trim())) throw new ValidationError('amount must be a non-negative number');
    const amount = Number(value);
    if (amount > Amount.MAX) throw new ValidationError(`amount must not exceed ${Amount.MAX}`);
    return new Amount(amount);
  }

  private constructor(readonly value: number) {}

  // Множення на курс із округленням до 4 знаків, щоб прибрати хвости плаваючої крапки (0.1 + 0.2)
  times(rate: number): number {
    return Math.round(this.value * rate * 1e4) / 1e4;
  }
}
  • Приватний конструктор + статичний parse. Це єдиний вхід. Якщо функція отримує CurrencyCode, їй не треба перевіряти, що це 3 великі літери: тип це гарантує.
  • Що змінилось відносно { ok, data }. Старий Parsed<T> примушував кожного викликача перевіряти ok. Виняток не дає «забути перевірку»: без нього код просто не дійде далі.
  • Amount.times(rate). Округлення до 4 знаків перенесено в клас суми: «як множити суму» — її відповідальність, а не сервісу.
  • CurrencyCode.of('USD') — для внутрішніх місць, де код відомий заздалегідь (базова валюта списку).

7. Модель: RatesSnapshot і Conversion

src/RatesSnapshot.tsзнімок курсів
import type { CurrencyCode } from './CurrencyCode';

// Знімок курсів однієї базової валюти на момент оновлення провайдером.
// Знає лише про себе: які валюти в ньому є і який курс до кожної.
export class RatesSnapshot {
  constructor(
    readonly base: CurrencyCode,
    private readonly rates: Readonly<Record<string, number>>,
    readonly updatedAt: string, // коли провайдер востаннє оновив курси (ISO, UTC)
  ) {}

  // Коди валют за абеткою
  currencies(): string[] {
    return Object.keys(this.rates).sort();
  }

  // Курс до валюти або undefined, якщо такої немає у знімку
  rateTo(code: CurrencyCode): number | undefined {
    const rate = this.rates[code.value];
    return typeof rate === 'number' ? rate : undefined;
  }
}
src/Conversion.tsрезультат конвертації
import type { Amount } from './Amount';
import type { CurrencyCode } from './CurrencyCode';
import { UnknownCurrencyError } from './errors';
import type { RatesSnapshot } from './RatesSnapshot';

// Результат конвертації. Створюється лише через Conversion.of, тож завжди узгоджений:
// результат точно дорівнює сумі × курс (з округленням).
export class Conversion {
  static of(snapshot: RatesSnapshot, to: CurrencyCode, amount: Amount): Conversion {
    const rate = snapshot.rateTo(to);
    if (rate === undefined) throw new UnknownCurrencyError(to.value);
    return new Conversion(snapshot.base.value, to.value, amount.value, rate, amount.times(rate), snapshot.updatedAt);
  }

  private constructor(
    readonly from: string,
    readonly to: string,
    readonly amount: number,
    readonly rate: number,
    readonly result: number,
    readonly updatedAt: string,
  ) {}

  // res.json(conversion) викликає цей метод сам: форма відповіді API визначена в одному місці
  toJSON() {
    return { from: this.from, to: this.to, amount: this.amount, rate: this.rate, result: this.result, updatedAt: this.updatedAt };
  }
}
  • Знімок захищає свої дані. Поле rates приватне й Readonly: ззовні видно лише currencies() і rateTo(). Сортування кодів і перевірка «курс — це число» зроблені тут один раз.
  • Conversion.of — фабричний метод: єдине місце, де є формула amount × rate і помилка «валюти немає». Приватний конструктор не дає створити суперечливий результат (з довільним result).
  • toJSON() визначає форму відповіді API: JSON.stringify і res.json викликають його самі. Тест перевіряє порядок полів.

8. Інтерфейс RatesProvider і його реалізація

src/RatesProvider.tsінтерфейс
import type { CurrencyCode } from './CurrencyCode';
import type { RatesSnapshot } from './RatesSnapshot';

// Те, що провайдер віддає сервісу: знімок курсів і момент, до якого його можна вважати свіжим.
export interface ProviderRates {

// Контракт «звідки беруться курси». RatesService залежить лише від цього інтерфейсу, а не від
// конкретного сервісу: щоб перейти на інший API, пишеш інший клас, який реалізує RatesProvider.

src/ExchangeRateApiProvider.tsimplements RatesProvider
import type { CurrencyCode } from './CurrencyCode';
import { ProviderError, UnknownCurrencyError } from './errors';
import type { ProviderRates, RatesProvider } from './RatesProvider';
import { RatesSnapshot } from './RatesSnapshot';

export interface ExchangeRateApiOptions {
  baseUrl: string;
  fallbackTtlMs: number; // на скільки вважати курси свіжими, якщо API не підказало час наступного оновлення
  fetchFn?: typeof fetch; // Dependency Injection: у тестах підставляємо підробку
  now?: () => number;
  timeoutMs?: number;
}

// Реалізація RatesProvider для ExchangeRate-API (open access). Єдине місце, що знає формат цього API:
// адресу, поля відповіді й те, як його статуси перетворюються на наші помилки.
export class ExchangeRateApiProvider implements RatesProvider {
  private readonly fetchFn: typeof fetch;
  private readonly now: () => number;
  private readonly timeoutMs: number;

  constructor(private readonly options: ExchangeRateApiOptions) {
    this.fetchFn = options.fetchFn ?? fetch;
    this.now = options.now ?? Date.now;
    this.timeoutMs = options.timeoutMs ?? 8000;
  }

  async fetchRates(base: CurrencyCode): Promise<ProviderRates> {
    const res = await this.request(base);
    const body = await this.readBody(res, base);
    return this.toProviderRates(base, body);
  }

  private async request(base: CurrencyCode): Promise<Response> {
    let res: Response;
    try {
      res = await this.fetchFn(`${this.options.baseUrl}/${base}`, { signal: AbortSignal.timeout(this.timeoutMs) });
    } catch {
      throw new ProviderError('Exchange rate provider is unreachable');
    }
    if (res.status === 429) throw new ProviderError('Exchange rate provider rate limit reached, try again later');
    if (res.status === 404) throw new UnknownCurrencyError(base.value);
    return res;
  }

  // Тіло відповіді має «довільну» форму (any): перевіряємо його вручну, перш ніж довіряти
  private async readBody(res: Response, base: CurrencyCode): Promise<any> {
    let body: any;
    try {
      body = await res.json();
    } catch {
      throw new ProviderError('Exchange rate provider returned invalid data');
    }
    if (body?.['error-type'] === 'unsupported-code') throw new UnknownCurrencyError(base.value);
    if (!res.ok || body?.result !== 'success' || typeof body.rates !== 'object' || body.rates === null) {
      throw new ProviderError('Exchange rate provider returned an error');
    }
    return body;
  }

  private toProviderRates(base: CurrencyCode, body: any): ProviderRates {
    const nextUpdateMs = Number(body.time_next_update_unix) * 1000;
    const expiresAt = nextUpdateMs > this.now() ? nextUpdateMs : this.now() + this.options.fallbackTtlMs;
    const updatedAt = new Date(Number(body.time_last_update_unix) * 1000).toISOString();
    return { snapshot: new RatesSnapshot(base, body.rates, updatedAt), expiresAt };
  }
}
  • Інтерфейс описує, що вміє постачальник курсів (fetchRates), а не як. RatesService знає лише інтерфейс. Це «залежність від абстракції»: хочеш інший API, пишеш інший клас з тим самим методом.
  • implements змушує компілятор перевірити, що клас справді має всі методи інтерфейсу.
  • Дрібні приватні методи (request, readBody, toProviderRates). Стара функція download була одним довгим блоком; тепер кожен крок названо й читається окремо.
  • Єдине місце, де є any. Тіло відповіді чужого API заздалегідь невідоме, тому readBody перевіряє його вручну, перш ніж довіряти, і лише потім з нього будуються наші типи.

9. RatesService і RatesCache

src/RatesCache.tsкеш
import type { CurrencyCode } from './CurrencyCode';
import type { RatesSnapshot } from './RatesSnapshot';

interface Entry {
  snapshot: RatesSnapshot;
  expiresAt: number;
}

// Кеш знімків курсів у памʼяті. Кожен запис живе до свого expiresAt.
// Годинник (now) передається в конструктор, тому в тестах час можна «крутити» вручну.
export class RatesCache {
  readonly #entries = new Map<string, Entry>();

  constructor(private readonly now: () => number = Date.now) {}

  // Свіжий знімок або undefined, якщо запису немає чи він застарів
  getFresh(base: CurrencyCode): RatesSnapshot | undefined {
    const entry = this.#entries.get(base.value);
    return entry && entry.expiresAt > this.now() ? entry.snapshot : undefined;
  }

  // Знімок навіть застарілий: потрібен як запасний варіант, коли провайдер недоступний
  getStale(base: CurrencyCode): RatesSnapshot | undefined {
    return this.#entries.get(base.value)?.snapshot;
  }

  set(base: CurrencyCode, snapshot: RatesSnapshot, expiresAt: number): void {
    this.#entries.set(base.value, { snapshot, expiresAt });
  }
}
src/RatesService.tsсервіс, Factory, Singleton
import { Amount } from './Amount';
import { AppConfig } from './AppConfig';
import { Conversion } from './Conversion';
import { CurrencyCode } from './CurrencyCode';
import { ExchangeRateApiProvider } from './ExchangeRateApiProvider';
import { ProviderError } from './errors';
import type { RatesProvider } from './RatesProvider';
import { RatesCache } from './RatesCache';
import type { RatesSnapshot } from './RatesSnapshot';

export interface RatesServiceOptions {
  config?: AppConfig;
  baseUrl?: string;
  fetchFn?: typeof fetch; // Dependency Injection: у тестах підставляємо підробку
  now?: () => number;
  fallbackTtlMs?: number;
}

// Сервіс курсів: бере знімки в провайдера, кешує їх і конвертує суми.
// Залежності (provider, cache) приходять у конструктор, тож сервіс не знає, звідки курси і де вони лежать.
export class RatesService {
  readonly #inFlight = new Map<string, Promise<RatesSnapshot>>();

  constructor(
    private readonly provider: RatesProvider,
    private readonly cache: RatesCache,
  ) {}

  // ── Factory: щоразу новий сервіс зі своїм кешем (зручно для тестів) ──
  static create(options: RatesServiceOptions = {}): RatesService {
    const config = options.config ?? AppConfig.defaults();
    const now = options.now ?? Date.now;
    const provider = new ExchangeRateApiProvider({
      baseUrl: options.baseUrl ?? config.ratesApiUrl,
      fetchFn: options.fetchFn ?? fetch,
      now,
      fallbackTtlMs: options.fallbackTtlMs ?? config.ratesFallbackTtlMs,
    });
    return new RatesService(provider, new RatesCache(now));
  }

  // ── Singleton: один спільний сервіс (і кеш) на весь застосунок ──
  // Без цього кожен новий сервіс мав би порожній кеш і зайвий раз ходив би до API з лімітом.
  static #shared: RatesService | undefined;

  static shared(): RatesService {
    RatesService.#shared ??= RatesService.create({ config: AppConfig.load() });
    return RatesService.#shared;
  }

  async getRates(base: CurrencyCode): Promise<RatesSnapshot> {
    const fresh = this.cache.getFresh(base);
    if (fresh) return fresh;

    // Одночасні запити на ту саму валюту ділять один виклик до провайдера
    let pending = this.#inFlight.get(base.value);
    if (!pending) {
      pending = this.refresh(base).finally(() => this.#inFlight.delete(base.value));
      this.#inFlight.set(base.value, pending);
    }
    return pending;
  }

  async listCurrencies(): Promise<string[]> {
    return (await this.getRates(CurrencyCode.of('USD'))).currencies();
  }

  async convert(from: CurrencyCode, to: CurrencyCode, amount: Amount): Promise<Conversion> {
    return Conversion.of(await this.getRates(from), to, amount);
  }

  private async refresh(base: CurrencyCode): Promise<RatesSnapshot> {
    try {
      const { snapshot, expiresAt } = await this.provider.fetchRates(base);
      this.cache.set(base, snapshot, expiresAt);
      return snapshot;
    } catch (err) {
      // Провайдер недоступний, а старі курси є: краще віддати їх, ніж помилку.
      // Помилку «такої валюти немає» (404) не підміняємо: вона правдива.
      const stale = this.cache.getStale(base);
      if (stale && err instanceof ProviderError) return stale;
      throw err;
    }
  }
}
  • Ін'єкція залежностей. new RatesService(provider, cache): сервіс не створює провайдер сам. У тесті в нього можна вставити StaticProvider без жодного fetch (див. розділ про тести).
  • RatesCache бере годинник у конструкторі. Тест «крутить» час вручну й перевіряє, що знімок протухає рівно в момент expiresAt.
  • getFresh і getStale. Два питання до кешу: «чи є свіже?» і «чи є хоч щось, навіть старе?». Друге потрібне, коли провайдер упав.
  • #inFlight зберігає Promise запиту, що вже виконується. Десять одночасних запитів на USD дають один виклик до API.
  • Статичні члени. RatesService.create() — фабрика, RatesService.shared() — Singleton із приватним статичним полем #shared. Вони не потребують екземпляра, тому прив'язані до класу.
  • Чому stale лише для ProviderError. Якщо API відповів «такої валюти немає» (404), це правда, і підмінювати її застарілими курсами не можна.

      AppConfig.toInt(env, 'PORT', 3000, 1, 65535),
      AppConfig.toInt(env, 'RATES_FALLBACK_TTL_SECONDS', 3600, 60, 86400),
      AppConfig.DEFAULT_API_URL,
    );
  }

  // Значення за замовчуванням, без .env і змінних середовища

  }

  // Для запуску застосунку: спершу підвантажує .env (він необовʼязковий), потім читає env
  static load(): AppConfig {
    try {
      process.loadEnvFile();
    } catch {
      // .env необов'язковий: є значення за замовчуванням
    }
    return AppConfig.fromEnv();
  }

  // Number('abc') дає NaN, тому перевіряємо, що змінна справді ціле число в межах
  private static toInt(env: NodeJS.ProcessEnv, name: string, fallback: number, min: number, max: number): number {
    const value = Number(env[name] ?? fallback);
    if (!Number.isInteger(value) || value < min || value > max) {
      throw new Error(`${name} must be an integer from ${min} to ${max}, got "${env[name]}"`);
    }
    return value;
  }

  private constructor(
    readonly port: number,
    readonly ratesFallbackTtlSeconds: number,
    readonly ratesApiUrl: string,
  ) {}

  get ratesFallbackTtlMs(): number {
    return this.ratesFallbackTtlSeconds * 1000;
  }
}

import { config } from './config';

export class RatesError extends Error {
  constructor(
    message: string,
    readonly status: number,
  ) {
    super(message);
  }
}

export interface RatesSnapshot {
  base: string;
  rates: Record<string, number>;
  updatedAt: string; // коли провайдер востаннє оновив курси (ISO, UTC)
}

export interface Conversion {
  from: string;
  to: string;
  amount: number;
  rate: number;
  result: number;
  updatedAt: string;
}

export interface RatesServiceOptions {
  baseUrl?: string;
  fetchFn?: typeof fetch; // Dependency Injection: у тестах підставляємо підробку
  now?: () => number;
  fallbackTtlMs?: number;
}

interface CacheEntry {
  snapshot: RatesSnapshot;
  expiresAt: number;
}

// Factory: кожен виклик створює незалежний сервіс зі своїм кешем (тести беруть свій).
export function createRatesService(options: RatesServiceOptions = {}) {
  const baseUrl = options.baseUrl ?? config.ratesApiUrl;
  const fetchFn = options.fetchFn ?? fetch;
  const now = options.now ?? Date.now;
  const fallbackTtlMs = options.fallbackTtlMs ?? config.ratesFallbackTtlSeconds * 1000;

  const cache = new Map<string, CacheEntry>();
  const inFlight = new Map<string, Promise<RatesSnapshot>>();

  async function download(base: string): Promise<RatesSnapshot> {
    let res: Response;
    try {
      res = await fetchFn(`${baseUrl}/${base}`, { signal: AbortSignal.timeout(8000) });
    } catch {
      throw new RatesError('Exchange rate provider is unreachable', 502);
    }
    if (res.status === 429) throw new RatesError('Exchange rate provider rate limit reached, try again later', 502);
    if (res.status === 404) throw new RatesError(`Unknown currency: ${base}`, 404);

    let body: any;
    try {
      body = await res.json();
    } catch {
      throw new RatesError('Exchange rate provider returned invalid data', 502);
    }
    if (body?.['error-type'] === 'unsupported-code') throw new RatesError(`Unknown currency: ${base}`, 404);
    if (!res.ok || body?.result !== 'success' || typeof body.rates !== 'object' || body.rates === null) {
      throw new RatesError('Exchange rate provider returned an error', 502);
    }

    const nextUpdateMs = Number(body.time_next_update_unix) * 1000;
    const expiresAt = nextUpdateMs > now() ? nextUpdateMs : now() + fallbackTtlMs;
    const snapshot: RatesSnapshot = {
      base,
      rates: body.rates,
      updatedAt: new Date(Number(body.time_last_update_unix) * 1000).toISOString(),
    };
    cache.set(base, { snapshot, expiresAt });
    return snapshot;
  }

  async function getRates(base: string): Promise<RatesSnapshot> {
    const cached = cache.get(base);
    if (cached && cached.expiresAt > now()) return cached.snapshot;

    // Одночасні запити на ту саму валюту ділять один виклик до провайдера
    let pending = inFlight.get(base);
    if (!pending) {
      pending = download(base)
        .catch((err) => {
          // Провайдер недоступний, а старі курси є: краще віддати їх, ніж помилку
          if (cached && err instanceof RatesError && err.status === 502) return cached.snapshot;
          throw err;
        })
        .finally(() => inFlight.delete(base));
      inFlight.set(base, pending);
    }
    return pending;
  }

  async function listCurrencies(): Promise<string[]> {
    const { rates } = await getRates('USD');
    return Object.keys(rates).sort();
  }

  async function convert(from: string, to: string, amount: number): Promise<Conversion> {
    const { rates, updatedAt } = await getRates(from);
    const rate = rates[to];
    if (typeof rate !== 'number') throw new RatesError(`Unknown currency: ${to}`, 404);
    // 4 знаки після коми, щоб прибрати хвости плаваючої крапки (0.1 + 0.2)
    const result = Math.round(amount * rate * 1e4) / 1e4;
    return { from, to, amount, rate, result, updatedAt };
  }

  return { getRates, listCurrencies, convert };
}

export type RatesService = ReturnType<typeof createRatesService>;

// Singleton: один спільний сервіс (і кеш) на весь застосунок.
// Без цього кожен новий сервіс мав би порожній кеш і зайвий раз ходив би до API з лімітом.
let sharedService: RatesService | undefined;

export function getRatesService(): RatesService {
  sharedService ??= createRatesService();
  return sharedService;
}

Тут усе разом: запит до API, розбір помилок, кеш, спільні запити, конвертація, Factory і Singleton. Працює, але щоб додати другий постачальник курсів чи замінити кеш, довелося б розрізати цю функцію. У новій версії кожна з цих частин окремий клас.

14. Вправи

  1. Другий провайдер. Напиши FrankfurterProvider implements RatesProvider (інший безкоштовний API). Які файли зміняться, окрім нового? (Підказка: лише RatesService.create або server.ts.)
  2. Кеш на диск. Зроби FileRatesCache з тими самими методами getFresh, getStale, set. Чи доведеться чіпати RatesService? Що треба зробити з типом кешу в його конструкторі (підказка: інтерфейс)?
  3. Нова помилка. Додай RateLimitError extends ProviderError для відповіді 429 і перевір, що ErrorHandler не змінився.
  4. Зламай навмисно. Зроби конструктор Amount публічним і створи new Amount(-5). Що тепер не гарантується? Який тест це не помітить?
  5. Поверни this. Зроби listCurrencies = async (...) => ... звичайним методом і подивись, що скаже Express при першому запиті. Чому стрілкове поле це лікує?
Перевір себе: чому RatesCache бере now у конструкторі, а не викликає Date.now() усередині?

Тоді тест може передати свій годинник і «пересунути» час на годину за мілісекунду. З прямим Date.now() довелося б чекати або підміняти глобальний час. Це та сама ін'єкція залежності, що й fetchFn.

Перевір себе: навіщо RatesService знає про ProviderError, а не про всі AppError?

Запасні (застарілі) курси доречні лише тоді, коли проблема на стороні провайдера (мережа, ліміт, збій). Помилка введення чи «валюти немає» правдива, і підміняти її старими даними неправильно. Окремий тип помилки дає змогу сказати це одним instanceof.
